# Портальная лига

Многопользовательская браузерная викторина по правилам «Своей игры». Один человек ведёт партию, от двух до восьми игроков выбирают вопросы и соревнуются за право ответа. Зрители подключаются по приглашению. Ведущий может принять устный ответ или прочитать сообщение, которое игрок отправил прямо в комнате.

## Начать играть

**Windows.** Установите Node.js 22.13 или новее. Откройте файл **Играть.cmd**. При первом запуске без готовых зависимостей сценарий установит их через npm. Окно сервера печатает адреса, браузер открывает лобби. Оставьте окно работающим до конца встречи.

**Linux, macOS или терминал Windows.** Откройте терминал в каталоге с этим README. Если папка node_modules отсутствует, выполните `npm ci`. Затем запустите `npm start`. Адрес ведущего — `http://localhost:3000`. Локальный режим автоматически создаёт SQLite-базу и каталог вложений в `data/`. Для импорта файлов SIQ также нужен Python 3.

1. Нажмите **Создать комнату** или выберите один из готовых пакетов. Введите свой ник и название встречи. В параметрах можно задать пароль, таймеры, штраф за неверный ответ и число мест.
2. Скопируйте приглашение из комнаты. Друзья в той же Wi-Fi или проводной сети открывают ссылку на своих устройствах. Если у компьютера несколько сетевых адаптеров, выберите из адресов в окне сервера тот, что относится к общей сети. Можно открыть этот адрес и ввести шестисимвольный код в лобби. При запросе брандмауэра Windows разрешите Node.js принимать подключения в используемой частной сети.
3. Друзья указывают ник и выбирают роль игрока. Когда вошли два игрока, ведущему доступна кнопка начала. Для демонстрации на одном компьютере подойдут три отдельных профиля браузера. Вкладки одного профиля разделяют одну учётную запись.
4. Выберите вопрос на табло. После чтения игрок нажимает кнопку ответа или пробел. Ведущий отмечает ответ как верный или неверный. В финале участники делают закрытые ставки и отвечают письменно. Итоговая таблица получает собственную ссылку.
5. Для игры со своими вопросами откройте **Пакеты → Новый пакет** (на главной — **Свой пакет**), создайте раунд и темы, заполните стоимость, вопрос и правильный ответ. Сохраните пакет и выберите его при создании комнаты. Черновик сохраняется на текущем устройстве.

Гостевой вход действует в текущем профиле браузера. Для входа с разных устройств используйте регистрацию. Оба пресета, «Измерение C-137» и «Аркадный космос», содержат по 12 вопросов на табло и по три темы финала, одну из которых разыграют участники.

## Запуск с PostgreSQL 16

Из каталога проекта, при работающем Docker Desktop или Docker Engine с Compose, выполните:

```sh
docker compose up -d --build
```

Откройте `http://localhost:3000`. На другом компьютере в сети укажите IP-адрес компьютера с Docker. Ведущему тоже можно открыть игру по этому адресу, чтобы кнопка приглашения скопировала ссылку для общей сети. При необходимости задайте в .env параметр `INVITE_ORIGIN=http://192.168.1.10:3000` со своим адресом. Команда `docker compose logs -f game` показывает журнал, `docker compose down` останавливает сервисы. База и вложения находятся в именованных томах `league_db` и `league_files`. Локальная SQLite-база и PostgreSQL — две самостоятельные установки со своими пользователями и партиями.

## Игра с друзьями через интернет

Разверните тот же проект на сервере с публичным адресом, Docker и актуальным Compose 2 с поддержкой `!reset`. Направьте DNS-запись своего домена на сервер и откройте входящие TCP-порты 80 и 443. Создайте в каталоге проекта файл `.env`. Пример значений:

```dotenv
DOMAIN=quiz.example.org
POSTGRES_PASSWORD=replace_with_long_random_alphanumeric_value
```

Выберите собственный домен и случайный пароль из латинских букв и цифр до первого создания тома PostgreSQL. Запуск:

```sh
docker compose -f compose.yaml -f compose.https.yaml up -d --build
```

Caddy обслуживает игровой домен по HTTPS и передаёт поток событий без буферизации. Откройте свой домен, создайте комнату и отправьте ссылку из лобби. Телефону игрока достаточно современного браузера. Игра обслуживается одним процессом Node.js на установку.

## Пакеты и медиа

Редактор поддерживает от одного до пяти обычных раундов и один необязательный финал. В теме обычного раунда помещается до десяти вопросов, в финальной теме — один. Допускаются обычные вопросы, «кот в мешке» и вопрос со ставкой. Изображения JPEG, PNG, GIF, WebP ограничены 5 МБ, MP3 и OGG — 10 МБ, MP4 и WebM — 50 МБ. Для внешних медиа используйте прямую ссылку на файл. Доступность стороннего источника зависит от сети игроков.

Можно переносить вопросы через JSON и импортировать совместимые SIQ-пакеты с текстом и одним медиафайлом на вопрос. Для архива действуют ограничения 50 МБ в сжатом виде, 100 МБ после распаковки и 2000 записей. Сложные сценарии SIQ с несколькими медиафрагментами требуют адаптации в редакторе. Экспорт JSON сохраняет ссылки на вложения. При переносе между установками перенесите также каталог media.

## Структура и проверка

| Каталог | Содержимое |
| --- | --- |
| client | Клиент на TypeScript и React, формы, редактор и игровой экран |
| public | Готовые к раздаче HTML, CSS, JavaScript, шрифт и иллюстрации |
| server/engine.ts | Конечный автомат игры, арбитраж кнопки, таймеры, ставки и финал |
| server/app.ts, server/rooms.ts | HTTP API, аутентификация, снимки по ролям, SSE и управление соединениями |
| server/schema.sql, server/storage.ts | Общая реляционная схема, транзакции SQLite и PostgreSQL |
| server/packs.ts, server/media.ts, server/siq.py | Редактор, проверки пакетов, вложения и импорт SIQ |
| tests | Автоматические проверки правил игры, HTTP, хранения и медиа |

Выполните `npm test` для запуска набора проверок. Встроенные тесты используют временные базы и не меняют игровые данные. Для пересборки изменённого клиента выполните `npm install` и `npm run build` в каталоге `client`. Скомпилированный клиент включён в проект.

Переменная `PORT` задаёт порт сервера, `DATA_DIR` — каталог локальных данных, `DATABASE_URL` — адрес PostgreSQL, `JWT_SECRET` — ключ подписи, `COOKIE_SECURE=true` включает защищённые cookie для HTTPS. Без внешнего ключа сервер при первом запуске генерирует ключ и сохраняет его в базе. Исполняемый файл Python для импорта SIQ можно задать переменной `PYTHON`.
